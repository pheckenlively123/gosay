<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| shell → main.go | User-supplied positional args cross from the shell into the process via `os.Args` |
| filesystem → go toolchain | `go.mod` content is read by the toolchain at build time |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01-01 | Tampering | go.mod toolchain pin | accept | Phase 1 ships `toolchain go1.26.3` — a downgrade attack against the local toolchain is out of scope for a CLI toy; Go's module checksum protection covers this for any consumer running `go install`. |
| T-01-01-02 | Information disclosure | main.go stdout/stderr | mitigate | main.go echoes user input verbatim (no PII, no secrets are involved); the walking-skeleton stub does not log to disk. No mitigation work required beyond keeping the stub trivial. |
| T-01-01-03 | Denial of service | main.go positional arg flood | accept | `strings.Join(os.Args[1:], " ")` is bounded by OS `ARG_MAX` (~2 MB on Linux, ~256 KB on macOS). Phase 1 does no further allocation. Effort to mitigate exceeds value for a CLI toy. |
| T-01-01-04 | Tampering | `.gitattributes` line-ending policy | mitigate | `cows/*.cow text eol=lf` lands in Plan 01-01 before any cow file is vendored in Plan 01-02; this is the load-bearing CRLF defense (PITFALLS.md #8). If `.gitattributes` were missing or wrong, Windows checkouts could corrupt cow art silently — acceptance criterion `grep -q "^cows/\*\.cow text eol=lf$" .gitattributes` enforces correctness. |
| T-01-01-SC | Tampering | npm/pip/cargo installs | n/a | No third-party packages installed in this plan. `go.mod` declares zero `require` entries. Package legitimacy gate not applicable to this plan; will activate in Plan 01-04 when `sebdah/goldie/v2` enters. |
</threat_model>
