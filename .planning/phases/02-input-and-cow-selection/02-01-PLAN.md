Add an exported sentinel error `ErrUnknownCow` to the `internal/cowsay` package and wrap it in `LoadCow` when the embedded read returns `fs.ErrNotExist` (D-12). Purpose: Establishes the error contract that the COW-05 user-facing slice (plan 02) depends on. Building it first means plan 02 receives the contract rather than discovering it.
Output: Modified `cowfile.go` (sentinel + wrapping), new sentinel test in `cowfile_test.go`.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| caller (main.go) → cowsay.LoadCow | `name` originates from the untrusted `-f <value>` CLI argument and is concatenated into an embed.FS lookup path (`"cows/" + name + ".cow"`) |
| error → terminal | error text from LoadCow may be printed to the user's terminal |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Information Disclosure | LoadCow error message | mitigate | Sentinel `ErrUnknownCow` carries only "unknown cowfile: <name>"; main.go (plan 02) renders `gosay: unknown cowfile %q` from the sentinel, never the raw path-bearing error. This plan provides the sentinel that makes path suppression possible. Severity: LOW (internal embed path, not a real secret) — mitigated regardless. |
| T-02-02 | Elevation of Privilege / Tampering | `"cows/" + name + ".cow"` embed.FS lookup with `..`/slash in name | accept | embed.FS is a read-only, compile-time, in-memory filesystem rooted at the binary; `fs.ValidPath` rules mean a traversal name simply fails to resolve and returns `fs.ErrNotExist` → routed to ErrUnknownCow. No disk access exists. Severity: LOW. No HIGH-severity threat in this plan. |
</threat_model>
